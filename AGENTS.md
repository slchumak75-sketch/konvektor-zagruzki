# AGENTS.md — передача работы следующему агенту

Этот файл — точка входа для любого агента (и человека), который продолжает работу
над «Конвектором загрузки». Прочитайте его целиком, затем
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) и [`docs/FORMATS.md`](docs/FORMATS.md).

## 1. Что это за проект

Windows-программа (Python + tkinter + PyInstaller), которая превращает счета,
накладные и прайсы поставщиков в одну таблицу Excel по образцу заказчика:

```
Штрихкод | Артикул | Наименование товара | ед. изм. | количество | цена |
сумма | ставка НДС | сумма НДС | сумма с НДС
```

Плюс математическая проверка (количество × цена, НДС по ставке, сумма + НДС)
и сверка с итогами документа. Сборка `.exe` — автоматически в GitHub Actions.

Заказчик присылает новые файлы поставщиков — их нужно поддерживать, не ломая
уже разобранные. **Корень репозитория — это «входящая папка» образцов.**

## 2. Правила работы (важно)

1. **Документируйте изменения.** Каждое изменение → запись в `CHANGELOG.md`
   (раздел «[Не выпущено]»), при новой особенности формата — в `docs/FORMATS.md`,
   при изменении алгоритма — в `docs/ARCHITECTURE.md`. Это требование заказчика.
2. **Держите «замки» тестов.** Все 10 образцов дают: 301 позицию,
   0 ошибок, 0 предупреждений, 140 рассчитанных значений. Если поменяли поведение
   осознанно — обновите числа в тестах и объясните причину в CHANGELOG.
3. **Первые 10 колонок листа «Данные» неизменны** (образец заказчика). Новые
   данные — только дополнительными колонками (по умолчанию выключены) или на
   служебные листы.
4. **Не оставляйте необработанные файлы молча.** Любой пропуск строки или файла
   должен попадать в `warnings`/`notes` и быть виден на листе «Сводка».
5. Язык интерфейса, сообщений и документации — **русский**. Комментарии в коде
   тоже на русском, с объяснением «почему», а не «что».
6. Никаких сетевых вызовов в рантайме. Никаких новых тяжёлых зависимостей:
   только `xlrd`, `openpyxl` (+ `pytest`, `pyinstaller` для разработки).
7. Ветка одна (та, в которой вы работаете), PR — из неё же. Не создавайте
   параллельных веток и не переименовывайте текущую.

## 4. Алгоритм добавления нового поставщика (пошагово)

1. Положите файл в корень репозитория (`git add` — он же станет тестом).
2. Прогоните:
   ```bash
   python -m konvektor.cli "новый_файл.xls" -o /tmp/out.xlsx
   python -m konvektor.cli "новый_файл.xls" -o /tmp/out.xlsx --json
   ```
   Смотрите `items`, `errors`, `warnings` и лист «Проверки».
3. Если позиций 0 — смотрите найденные шапки:
   ```bash
   python - <<'PY'
   from konvektor.readers import read_source
   from konvektor import detect
   sf = read_source("новый_файл.xls")
   for sh in sf.sheets:
       for i, row in enumerate(sh.rows):
           h = detect.detect_header(row, i)
           if h: print(sh.name, i + 1, h.cols)
   PY
   ```
   Пусто → добавьте синоним заголовка/уберите мешающее слово из `_REJECT`.
4. Если позиций мало/много — смотрите, какие строки пропущены (`res.warnings`)
   и не попадает ли итоговая строка в позиции.
5. Проверьте арифметику: на листе «Проверки» не должно быть `ОШИБКА` по корректному
   документу. Типичная причина — выбрана не та из двух колонок «цена» (см.
   `_BAD_PRICE_HINTS`) или неверный режим НДС.
6. Добавьте файл в `tests/conftest.py::KNOWN_FILES` (ожидаемое число позиций)
   и описание в `docs/FORMATS.md`.
7. `python -m pytest` — всё зелёное.
8. `CHANGELOG.md` → запись; коммит; пуш в текущую ветку (сборка в Actions
   запустится сама).

## 5. Как проверить, что ничего не сломано

```bash
python -m pytest -q                    # 307 тестов, должно быть «все прошли»
python -m konvektor.cli --selftest .    # «САМОПРОВЕРКА: OK — … 301 позиция, 0 ошибок»
```

Для Windows-сборки: после пуша зайти в Actions и убедиться, что job
`Сборка .exe (Windows)` зелёный и артефакт `Konvektor-windows` появился.
В этом job собранный `.exe` дополнительно проверяется командами `--version`,
`--explain "КХ2104033 (1).xls"`,
`--diagnose "КХ2104033 (1).xls"` и `--selftest .`; вывод `--diagnose` на образце
должен содержать «Прочитан как» и число позиций.

Если пользователь пишет «файл не конвертируется», первым делом просите вывод
`Konvektor-cli.exe --diagnose "имя файла.XLS"` — там формат, листы, реквизиты,
количество позиций и полный traceback.

## 6. Известные ограничения (не баги, а осознанные решения)

* Штрихкод ищется только в наименовании и в явной колонке. Штрихкод, спрятанный
  в другой колонке (например, в «Примечании»), не извлекается.
* Суммы прописью не распознаются как числа (это защита от ложных сверок).
* Файлы с паролем, PDF-сканы, `.ods`, `.dbf` не поддерживаются.
* Кириллические артикулы извлекаются только если начинаются с кириллической
  буквы (`АБ123`), т.к. продолжение токена — латиница/цифры.
* Режим НДС определяется на файл целиком; документ со смешанными режимами
  (часть строк с НДС в том числе) будет проверен по преобладающему.
* Окно не поддерживает drag-and-drop внутрь окна (нужен tkdnd); вместо этого
  можно перетащить файлы на ярлык `Konvektor.exe`.
* Реквизиты (поставщик, номер и дата документа) — **справочные**: они пишутся
  в «Сводку» и журнал, но не влияют на перенос данных. Если в файле их нет
  (например, `Счет СЧЦБ-17059130.xlsx` — там только таблица товаров),
  программа честно пишет «— не найден»/«—», а не выдумывает значение.

### Анализ раскладки — на что не наступить второй раз

* **Два контура, а не один**: подписи (`detect.py`) и данные (`layout.py`).
  Если правите распознавание — сначала проверьте, не решается ли это
  проверкой по данным (профиль колонки, арифметика), иначе распознавание
  превратится в набор частных случаев.
* **Корпус раскладок**: любое новое правило обязано не сломать
  `tests/synthetic.py` (13 раскладок одного документа) и `--selftest .`
  (301 позиция). Правило, ухудшающее метрику, — неверное.
* **Склейка шапки** применяется только когда даёт строго больше ролей, чем
  любая из строк, и верхняя строка — подписи (≥3 непустых, без чисел).
  Без этого «I. ТОВАРНЫЙ РАЗДЕЛ» + шапка ТТН-1 съедали настоящую шапку и
  столбец «№» становился наименованием.
* **`repair_numeric_roles`** срабатывает только при арифметике ниже 0.8 и
  улучшении ≥0.25; проверки учитывают оба режима НДС (сверху и «в том числе»),
  иначе файлы с ценами «с НДС» начнут переставлять колонки.
* **Транспонирование** — только если шапки в строках нет вообще; в развёрнутой
  таблице `Item.row` = номер столбца исходного листа.
* **Доверие** — не «оценка красоты», а свёртка покрытия полей, арифметики и
  полноты. Меняя формулу, обновите `docs/КОНЦЕПЦИЯ.md` и `tests/test_analysis.py`.

### Реквизиты документа — на что не наступить второй раз

* **Даты в `.xls` — это `XL_CELL_DATE`**, а не число и не строка: до 1.1.0
  `readers._xls_value` возвращал для них `None`, и дата документа терялась
  (например, у «Лидского пива»). Теперь возвращается `datetime.date`
  через `xlrd.xldate_as_datetime(cell.value, wb.datemode)`.
* **Тип документа — только словами целиком** (`\bакт\b`, `\bсчет\b`):
  подстрочный поиск давал «Акт» из слова «унитаза-компакт» и «Счет»
  из «расчет».
* **Название поставщика не режется по запятой и не теряет кавычки**:
  `clean_supplier` снимает только пробелы/точки/точки с запятой по краям.
* **Число и дата ищутся вместе, но кандидаты оцениваются**: пара со словом
  «Счет/ТТН/Накладная» и «от» выигрывает, текст со словом «договор» штрафуется.
  Иначе вместо «ТТН-1 № 1019250 от 12.11.2026» подхватывался
  «Договор № 528 от 31.05.2016».
* **Обрезанный «хвост» строки ломает дату**: если взять `text[m.end(): m.end()+12]`,
  от `12.11.2026` останется `19.10.20` и получится 2020 год. Берите с запасом.
* `looks_like_company` отбрасывает адреса (`гп. Мир, ул. …`), УНП и подписи,
  поэтому «первое название организации на листе» больше не даёт мусор.
* Тесты на всё это — `tests/test_meta.py` (в том числе таблица ожидаемых
  реквизитов по всем 10 образцам: `EXPECTED`).

## 7. Что стоит сделать дальше (идеи бэклога)

1. Запоминать последнюю папку/настройки в `%APPDATA%\Konvektor\settings.json`.
2. Подсветка ошибок прямо в листе «Данные» (красная заливка ячеек с расхождением).
3. Сопоставление товаров со справочником (по штрихкоду/артикулу) и заполнение
   пустых артикулов из накопленной базы.
4. Экспорт «Проверок» в отдельный CSV для бухгалтерии.
5. Проверка дублей позиций в пределах одного документа.
6. Опционально — перенос страны происхождения/веса на отдельный лист
   (сейчас эти колонки сознательно отбрасываются).

## 8. Быстрая справка по git/CI

```bash
git status && git diff            # что изменилось
git add -A && git commit -m "..." # коммит
git push origin HEAD              # пуш в текущую ветку -> автосборка
gh run list --limit 3             # состояние сборок
gh run watch                      # следить за последней
gh release list                   # релизы
```

Тег `vX.Y.Z` + пуш тега → релиз с `.exe` (см. `docs/DEVELOPMENT.md`).
