# Архитектура

```
                 ┌──────────────┐        ┌───────────┐
  файл (.xls/.xlsx/.csv/.html)
                 │  readers.py  │  Sheet │ detect.py │ шапка: смысл -> колонка
                 └──────┬───────┘        └─────┬─────┘
                        │  «сырые» значения    │
                        ▼                      ▼
                 ┌────────────────────────────────┐
                 │          extract.py            │  блоки таблиц -> Item
                 │  (штрихкод/артикул из текста)  │
                 └───────────────┬────────────────┘
                                 ▼
                 ┌────────────────────────────────┐
                 │          validate.py           │  арифметика + достройка
                 │  режим НДС, допуски, итоги     │
                 └───────────────┬────────────────┘
                                 ▼
                 ┌────────────────────────────────┐
                 │           writer.py            │  Данные / Проверки / Сводка
                 └───────────────┬────────────────┘
                                 ▼
                          итоговый .xlsx

  pipeline.py — склеивает всё, cli.py и gui.py — два интерфейса к нему.
```

Ключевой принцип: **никакой привязки к именам файлов и номерам колонок**.
Всё определяется по содержимому: заголовки сопоставляются словарю синонимов,
формат — магическим байтам, числа — универсальным парсером.

## Модули

## Поток данных

1. `pipeline.convert` разворачивает аргументы (`collect_files`) и для каждого файла
   вызывает `read_source` → `extract_file`.
2. `read_source` определяет формат по магическим байтам (`PK..` → xlsx,
   `D0CF11E0..` → xls, начинается с `<` → html, иначе csv) и читает **все** листы.
   При ошибке пробует следующие ридеры (частый случай: `.xls`, внутри которого xlsx
   или HTML).
3. `extract_file` по каждому листу находит **все** шапки (`detect_header`) и режет
   лист на блоки. Внутри блока каждая строка классифицируется: нумерация
   (`1 2 3 4 …`) → пропуск, итог (`итого/всего/…`) → `DocTotal`, остальное → `Item`.
4. `validate_items` определяет режим НДС по каждому исходному файлу, достраивает
   отсутствующие значения и проверяет арифметику; `check_document_totals` сверяет
   найденные в документах итоги с суммами строк.
5. `writer.write_workbook` пишет три листа и стили.

## Ключевые алгоритмы

### 1. Определение смысла колонки (`detect.classify_header`)

Возвращает `(kind, quality)`. Порядок правил важен:

1. «мусорные» колонки отсекаются списком `_REJECT` (ТНВЭД, масса, страна, фасовка…);
2. `штрих`/`ean`/`barcode` → `barcode`;
3. `артикул`/`арт.` → `article`;
4. `ставка` → `vat_rate`;
5. `цена` → `price` (бонусы за «б/НДС», штрафы за «отпускная», «доставка», «с НДС»);
6. `ндс` → `sum` (если «без НДС»), `total` (если «с НДС»/«всего»), иначе `vat_sum`;
7. `всего`/`итого` → `total`;
8. `кол*`/`к-во`/`количество` → `qty` **до** правила наименования
   (иначе «Количество продукции» станет наименованием);
9. `наимен`/`номенклатур`/`товар`/`продукц`/`материал` → `name`;
10. `ед` + `изм` → `unit`; `сумм`/`стоимост` → `sum`; `код` → `article`.

`quality` разрешает неоднозначность: при нескольких колонках одного смысла
остаётся колонка с максимальным качеством (пример: «Цена шт. б/НДС» побеждает
«Цена шт. с НДС»).

Шапка признаётся, если есть `name` и не меньше двух из `qty/price/sum/total`,
всего не меньше 4 распознанных колонок (`detect_header`).

### 2. Штрихкод и артикул из наименования

* `find_barcode_in_text` — регулярка `(?<![\d.,])(\d{8}|\d{12}|\d{13}|\d{14})(?!\d)(?![.,]\d)`.
  Lookahead `(?![.,]\d)` не даёт поймать часть десятичной дроби, lookbehind —
  часть длинного числа. Кандидаты фильтруются проверкой контрольной цифры EAN
  (`ean_ok`), при равенстве предпочитается 13-значный. Это отсекает
  `ТУ BY 812004107.016-2018`, телефоны и номера деклараций.
* `find_article_in_text` — шаблоны `арт./артикул/код/code` + ведущий код вида
  `8160612 Вода…`. Перед поиском маскируются штрихкод и слова «штрих-код»,
  чтобы не принять код за артикул; кандидат обязан содержать цифру и не быть
  служебным словом (`_ART_STOP`).

### 3. Итоговые строки и их смысл

`detect.total_label` ловит строки, начинающиеся с «итого/всего/в том числе/сумма НДС…».
`total_scope` решает, с чем сверять: «по листу/по странице» → только свой блок,
иначе накопительно по документу. `total_field_from_label` определяет, **что**
означает итог («Сумма без НДС :» → сумма; «… НДС» → НДС; «… с НДС/к оплате» → сумма
с НДС; «масса/доставка/прописью» → не сверять). Если смысл не ясен, сверяются все
распознанные колонки, а при отсутствии таковых — проверяется, сходится ли число
хоть с одним агрегатом (иначе предупреждение).

### 4. Режим НДС

`detect_vat_mode` считает суммарное отклонение двух гипотез по строкам, где есть
и «сумма», и «сумма НДС», и ставка:

```
НДС сверху:      vat ≈ sum × rate / 100
НДС в том числе: vat ≈ sum × rate / (100 + rate)
```

Побеждает гипотеза с меньшим отклонением; она же используется при достройке
и при проверках. Все образцы — «НДС сверху».

### 5. Проверки и достройка (`validate.py`)

Порядок: сначала достройка (например, `сумма = кол-во × цена`, затем
`НДС = сумма с НДС − сумма`, затем `сумма с НДС = сумма + НДС`), потом проверки.

* допуск по деньгам — `MONEY_TOL = 0.02` (два округления до копеек);
* допуск по количеству — `QTY_TOL = 0.002`;
* для проверки «НДС по ставке» допуск дополнительно масштабируется ставкой
  (`max(0.02, 0.011 × rate)`);
* каждая достройка → `Issue(severity="info")` + запись в `item.computed`,
  которая превращается в жёлтую заливку в Excel;
* несоответствия → `severity="error"`;
* нестандартная ставка (не 0/5/7/10/20/25) → `severity="warning"`;
* расхождение с итогом документа → `severity="warning"` с допуском
  `max(0.05, 0.1 % от значения)`.

### 6. Запись (`writer.py`)

* «Данные»: 10 колонок образца (+2 опциональные: «файл», «строка»),
  шапка с заливкой, закрепление `A2`, автофильтр, ширины колонок, числовые форматы
  (`#,##0.00`, `#,##0.###`), штрихкод и артикул — **текстом** (`@`), иначе Excel
  исказит длинные числа и ведущие нули;
* итоговая строка — формулы `=SUM(...)`, поэтому пересчитывается при правках;
* «Проверки»: тип, файл, строка, наименование, поле, значение в документе,
  расчёт, разница, комментарий; цветовая заливка по типу;
* «Сводка»: статистика по файлам, итог, легенда, замечания по чтению.

## Расширение

* Новый заголовок колонки → строка в `detect.classify_header` + кейс в
  `tests/test_detect.py`.
* Новый формат файла → новая функция `_read_xxx` в `readers.py`, ветка
  в `sniff_kind` и в списке `attempts` функции `read_source`.
* Новое правило арифметики → функция в `validate.py` + тест в
  `tests/test_validate.py`.
* Новый столбец в итоговой таблице → `TEMPLATE_COLUMNS` в `__init__.py`,
  `COLUMN_WIDTHS`/`_write_data_sheet` в `writer.py`, при необходимости `Item`.
  Внимание: колонки образца должны остаться первыми десятью.

## Инварианты (не нарушать)

1. Первые 10 колонок листа «Данные» — всегда `TEMPLATE_COLUMNS` в том же порядке.
2. Штрихкод и артикул в Excel — текст.
3. Никаких сетевых вызовов: программа работает офлайн.
4. Один битый файл не должен останавливать обработку остальных.
5. Любое рассчитанное значение обязано быть помечено (`item.computed`) и попасть
   на лист «Проверки».
6. Все 10 образцов должны давать 301 позицию и 0 ошибок — это проверяют тесты.
